# Протокол синхронізації AniSyns (версія 1)

Призначений для сумісності iOS/iPadOS-застосунку й майбутнього ПК-клієнта. Усе — звичайний HTTP + JSON у локальній мережі.

## 1. Ідентичність
Кожен пристрій має `id` (16 hex), `name` (до 30 символів) і `epoch` (12 hex, генерується при створенні стану; змінюється, якщо стан скинуто).
Аніме ідентифікується `kid = sha1(key)[:10]`, де `key = "<url сторінки аніме>||<озвучка або порожньо>"` — однаковий на всіх пристроях.

## 2. Пошук пристроїв
* **UDP-маячок** на порт `8791` (широкомовлення `255.255.255.255` і `<підмережа>.255`), кожні ~20 с, коли синхронізацію ввімкнено:
  `{"t":"anisyns","p":1,"id":"…","name":"…","port":8790}`. Адреса відправника UDP-пакета = адреса пристрою.
* **Запасний пошук**: `GET http://<ip>:8790/sync/hello` по всій підмережі /24 → `{"app":"anisyns","proto":1,"id":"…","name":"…","port":8790}`.
* Ручне додавання за IP.

## 3. Сервер синхронізації
Окремий HTTP-сервер на `0.0.0.0:8790` (працює лише коли синхронізацію ввімкнено). Основний API застосунку лишається на `127.0.0.1` і ззовні недоступний.

## 4. Спарювання (одноразово)
1. A → B: `POST /sync/pair_request` `{"id":A_id,"name":A_name,"port":8790}`. B показує 4-значний код (діє 120 с).
2. Користувач вводить код на A. A → B: `POST /sync/pair_confirm` `{"id":A_id,"code":"1234","port":8790}`.
3. Відповідь `{"ok":true,"secret":"<64 hex>","id":B_id,"name":B_name,"port":8790}`. Обидві сторони зберігають `secret` для пари.
Після 5 хибних кодів запит скасовується. Обмеження: код і секрет ходять по HTTP без шифрування — модель загроз це домашня/довірена мережа.

## 5. Підписані запити
Усі запити, крім `/sync/hello`, `/sync/pair_*`, мають заголовки:
`X-Sync-Id: <id відправника>`, `X-Sync-Ts: <unix мс>`, `X-Sync-Sig: hex(HMAC_SHA256(secret, "<ts>.<path>.<sha256_hex(тіла)>"))`.
Сервер відхиляє запит, якщо підпис невірний або `|now − ts| > 120 с` (HTTP 401).

## 6. Стан = регістри
Кожна зміна — регістр `{"v": значення, "ts": мс (гібридний логічний годинник), "dev": id автора, "seq": локальний лічильник}`.
Перемагає регістр із більшим `(ts, dev)`. Ключі:

| ключ | значення |
|---|---|
| `i/<kid>` | опис аніме (`key,url,title,dubbing,base_dub,all_dubs,folder,known,ep_titles,meta,sources,poster_v`) або `{"del":1}` (видалено) |
| `w/<kid>/<серія>` | `1` переглянута, `0` знято позначку |
| `p/<kid>/<серія>` | позиція відтворення, секунди |
| `f/<kid>` | `{"a":архів,"al":власна назва,"g":група,"gn":назва групи}` |
| `s/<назва>` | налаштування (лише якщо ввімкнено «синхронізувати й налаштування»): `auto_skip, auto_skip_opening, auto_skip_ending, auto_next, auto_check, auto_check_hours, blur_thumbs, np_ep_cover, skip_mode, vol_max, own_vol, recent_min, site_order` |

Зміни виявляються порівнянням поточного стану з останнім зафіксованим (без вбудовування в кожну функцію застосунку); завантажені файли не синхронізуються.

## 7. Обмін
`POST /sync/exchange` (підписаний): тіло
`{"regs":{ключ:регістр,…},"since":N,"epoch":"<epoch співрозмовника, який ми знаємо>","name":"…","port":8790}` —
`regs` = мої регістри з `seq` більшим за підтверджений для цього пристрою (`out_seq`), `since` = `seq` співрозмовника, до якого я вже отримав дані (`in_seq`).
Відповідь: `{"ok":true,"epoch":"…","seq":M,"regs":{…регістри з seq > since…},"name":"…","now":мс}`.
Якщо `epoch` у відповіді не збігається зі збереженим — співрозмовник скинув стан: `in_seq=out_seq=0` і повторити.
Після успіху: `out_seq = мій seq на момент відправки`, `in_seq = seq з відповіді`. Операція ідемпотентна.

## 8. Команди
`POST /sync/command` (підписаний):
`{"type":"download","item":<опис як у i/…>,"eps":[1,2],"quality":"720p"}` → `{"ok":true,"queued":N}` — додати аніме (якщо його ще немає) й поставити серії в чергу завантаження.

## 9. Примітки для ПК-клієнта
* Реалізувати: UDP-слухач/маячок, `/sync/hello`, `/sync/pair_*`, `/sync/exchange`, `/sync/command`, підпис HMAC, регістри з LWW.
* Годинники пристроїв мають бути приблизно синхронні (NTP); значна розбіжність дає «нечесний» LWW.
* iOS вимагає дозволу «Локальна мережа» (запитується при першому пошуку).

## v1.1 — пристрої, перекидання сеансу, пульт

- Поле `kind` (`phone|tablet|pc`) у beacon, `/sync/hello`, `pair_request`, `exchange`; користувацький псевдонім пристрою зберігається лише локально (`peers[id].alias`).
- Команди через `POST /sync/command` (підписаний запит):
  - `{type:'handoff', item?, kid, hash, scroll, search, play?:{n,t,paused}, mode:'handoff'|'cast', from}` — приймач створює тимчасовий запис (`item.temp=true`), якщо його немає, і віддає UI `handoff` (з `hid`) у `/api/sync`; UI підтверджує `/api/sync_ack`.
  - `{type:'pstate'}` → `{ok, state:{on,id,n,t,dur,paused,title,ep}}` (стан плеєра; `on:false`, якщо звіту не було >6 с).
  - `{type:'pcmd', c:'play|pause|seek|seekby|next|prev|close', v}` — команди пульта; плеєр забирає їх зі своїм звітом `/api/pstate`.
- Локальні ендпоінти UI: `/api/sync_alias`, `/api/sync_cast`, `/api/sync_rc`, `/api/sync_pstate`, `/api/sync_ack`, `/api/pstate`.
